# Appendix B ("Symmetry sectors (cross-check)"): executable evidence

This folder answers the referee remark *"Appendix B's exhaustive sectors need executable evidence. None was independently
rerun here."* It holds the search codes that produced Appendix B of the p10 AME manuscript (`paper/main.tex`, section
`app:sym`: Propositions 2 = `prop:loc` and 3 = `prop:aut`, and Table VI = `tab:sectors`), copied from the run's working
directories, made self-contained, and wired to one replay script. Each check compares its output with the numbers printed
in the paper or in the original logs.

Appendix B is a cross-check. By Theorem `thm:bms` (Ball–Moreno–Simoens) and the frame search of Sec. `sec:classify`,
no qubit-pair stabilizer AME(8,4) exists at all, so every sector below is empty for that reason too. The computations
here were written before those results, independently of the frame enumeration.

## Quick start

```bash
./run.sh                 # = ./run.sh quick: 39 checks, about 16 min on one core (unloaded laptop), see "Runtimes"
./run.sh full            # all 60 checks, about 100 min of CPU; JOBS=4 ./run.sh full takes about 30 min of wall time
./run.sh list            # the checks, their tier and the Appendix-B claim each one covers
./run.sh c7_auditor      # one or more named checks
PYTHON_NUMPY=/path/to/python-with-numpy ./run.sh quick
```

**Requirements:** `bash` (3.2 or later), a C compiler (`cc`; `-O2`; sources are compiled into `build/` at run time),
and Python ≥ 3.9. 36 checks use the standard library only. **24 checks need numpy** (tested with numpy 2.5.4 and, for some
checks, 2.4.2, on Python 3.14; `z3twist.py` has its own fallback for `np.bitwise_count`, which is numpy ≥ 2.0; numpy 1.x
was not tested). The numpy checks are marked
`np` in `checks/LIST`. If no numpy is found they are reported as `SKIP` and the verdict is `INCOMPLETE` (exit code 2).
Exit codes: 0 = all PASS, 1 = at least one FAIL, 2 = no FAIL but some SKIP. No network access is needed or used. Each
process stays below 1.5 GB of memory (the largest is `c5audit.py`, about 1.4 GB peak footprint, 1.0 GB RSS), and
`run.sh` starts every check under `nice -n 10`.

Environment variables: `PYTHON` (default `python3`), `PYTHON_NUMPY` (default: `$PYTHON` if it imports numpy),
`CC` (default `cc`), `JOBS` (checks run in parallel, default 1).

## How a check works

`checks/LIST` registers the checks (`ID | tier | needs | claim`). `checks/ID.sh` runs the computation in a fresh scratch
directory `work/ID/`. It writes the **canonical output** (deterministic lines only: no timings, no machine-dependent
values) to `out/ID.txt` and the raw log to `out/ID.log`. `run.sh` compares `out/ID.txt` with `expected/ID.txt`,
ignoring `#` lines and blank lines, and prints PASS/FAIL per check and an overall verdict (on failure, see
`out/ID.diff`). Every `expected/ID.txt` starts with a `#` header that quotes the paper sentence, the board post and the
original log file the numbers come from.

## Hand derivations

Where a step has no search, the derivation is quoted here. The original texts are in `docs/`. Each step has been
re-derived by the second agent unless stated otherwise.

**H1. Mixed H/S parties (Prop. `prop:loc`, argument.md 5.2).** Write the symplectic form as B = Tr(β + σ) with β
F_4-bilinear and σ F_4-sesquilinear. On H parties β = 0 and on S parties σ = 0. S = S^⊥ and F_4-closed gives
β = σ = 0 on S × S. The projection π_S(S) to the S-type parties is β-isotropic in a nondegenerate space, so its
F_4-dimension is at most a_S. Likewise π_H(S) has dimension at most a_H. Since a_S + a_H = 8 = dim_F4 S,
S = π_S(S) ⊕ π_H(S), a product state across (H | S). The smaller group has ≤ 4 parties and a pure reduced state, which
is not maximally mixed. Single author (auditor), reviewed by pairs. The M-type counting is executable (`m_type_counting`).

**H2. Prop. `prop:aut` (a) (pairs #191(1), audited #199).** Let Ω = P_σ g. Because P_σ is symplectic,
Ω^† = g^† P_σ^{-1}. For x, y ∈ S, ω(x, Ω^† y) = ω(Ωx, y) = 0, so Ω^† S ⊆ S^⊥ = S. Hence Ω^†Ω = g^†g is a local linear
automorphism of S. It equals 1 by Prop. `prop:loc`, so every g_j is symplectic.

**H3. Prop. `prop:aut` (b) (argument.md 5.3 corollary; correction in board #132).** Ω^{ord σ} is local, hence 1. So the
product of the local maps around every cycle of σ is 1, and a local change of basis along each cycle makes Ω a pure
permutation on the moved parties. On a fixed party only h_j^{ord σ} = 1 survives. Replacing Ω by a power gives prime
order ℓ. For ℓ = 7, h = 1 because Sp(4,2) has no element of order 7 (`group_orders`).

**H4. Completeness of the sector list (closure note, item 3).** A permutation of 8 parties of prime order ℓ has cycle
type (ℓ^k, 1^{8−kℓ}). `group_orders` prints all of them. The twists on fixed parties are elements h of Sp(4,2) with
h^ℓ = 1. For ℓ = 3 they are classified by the fixed space (dimension 4, 2 or 0: h = 1, a = 2, fixed-point-free), and
for ℓ = 5 an order-5 h is fixed-point-free. For ℓ = 2 the involutions are classified by rank(1+h) ∈ {0, 1, 2}; the
(2^t) rows treat every rank inside the derivation (argument.md 5.4, 5.7; board #161, #163, #165). Nobody re-checked
this list independently during the run (closure note, item 3). The enumeration printed by `group_orders` is new in this
release.

**H5. Row (2,1^6) (pairs #165, re-derived by the auditor #169).** K = S^Ω = ker N|_S with N = 1+Ω, d = dim K ≥ 8,
since NS ⊆ K and dim NS = 16 − d. K injects into (w, f_a, f_b) for any two fixed parties, because the kernel lives on
the other 4 parties, so d ≤ 12 − r_a − r_b. NS_0 = NS ∩ {w = 0} has dimension ≥ 12 − d. It lives on the six fixed
blocks with weight ≥ 5, so it injects into any two of them: dim NS_0 ≤ r_c + r_e. Hence all r_j are equal to some r,
d = 12 − 2r, and r ≤ 2. If r = 0, NS ⊆ {(w,w)} has weight ≤ 2, so NS = 0, contradicting d ≤ 12. If r = 1, NS_0 is a
binary [6,2,≥5] code, which cannot exist. If r = 2, NS_0 is an OA(16,6,4,2) of index 1, which exceeds the Rao bound
(16 < 19) and the Bose–Bush bound (≤ 5 factors). `inv1_counting` runs the chain over all 729 patterns and the two code
checks.

**H6. Row (3^2,1^2), mixed (auditor #168, pairs #191(3), audited #199).** V_nf has F_4-dimension 8 + r_6 + r_7 and
T = S ∩ V_nf is a Lagrangian of it, so r_6 + r_7 is even. For (2,0), T ∩ (A_nf + N_6) has dimension
≥ 5 + 6 − 10 = 1, and its words live on 4 parties. `z3mixed_counting` lists all 9 cases.

**H7. Row (5,1^3) (pairs #175 (C), re-derived by the auditor #184).** Words of S^Ω with cycle constant 0 live on the
n1 untwisted parties (weight ≤ 3), so 2 + 2n1 = dim S^Ω ≤ 4. S_nf is an F_16-Lagrangian of F_16-dimension 4 + n5, so
n5 is even. Hence n5 = 2 and n1 = 1 (`c5_counting`). L ∩ C has F_16-dimension 1 (the 331 500 graph-type generators,
computed twice) or 2 (1625 generators, each with a weight-2 word; by hand in #184, computed by `c5_nongraph`).

The reductions in front of every computational row (for example S = S^Ω ⊕ S_nf, the graph form of S_nf, and
(C, β) for (2^4)) are hand derivations too. They are written out in `docs/argument_sec5.md` (5.4–5.8) and the board
posts, and the second agent re-derived each of them (`docs/ame84_f2linear_closure.md`). The validation scripts
(`c5twist_val.py`, `c7dbg.py`, `val_inv8.py`, `inv4_validate.py`, `z3a_val.py`, `z3twist6.py`) check them numerically:
they rebuild S as 16-qubit stabilizer rows and compare direct 2^16-word enumerations with the reduced formulas.

## Discrepancies and caveats

1. **"at threshold 4 it finds 1.4×10^6" (row (2^3,1^2)) is a time-capped count.** The original run
   (`t3lift_4_0_2.log`) stopped after 200 s of wall-clock time with 1 433 150 solutions and the threshold-4 tree
   unfinished. The release reproduces this number exactly, with the same per-level profile, by replacing the clock
   with a solution cap (`T3_MAXSOL=1433150`, check `inv3_auditor_ctrl`). The number is a property of the cap and not
   of the sector. Revision 4 of the paper says "at threshold 4 a capped search finds more than 1.4×10^6".
2. **The (2^4) row had no positive control in the original sources.** It had only validations of the reduction
   (`val_inv8.py`, `val2_inv8.py`, `dump_check.py`, `inv4_validate.py`). The relaxed-threshold control
   `extra/inv8_thr3_ctrl.py` (`inv4_pairs_ctrl`) was added for this release with pairs' own `inv8.c`.
3. **Three rows have no relaxed-threshold-4 control:** (3^2,1^2) h = 1, (5,1^3) and (7,1). Their searches cover the
   whole space and report the minimum weight of every candidate: exactly 4 for all 77 760 maps; 4 for 273 000 of the
   331 500 Lagrangians; best 4 over all 5917 subspaces. Weight-4 states are therefore exhibited, and the direct-
   enumeration validations (`c5twist_val.py`, `c7dbg.py`, `z3_check.py`) check the formulas. The paper's "in most
   cases a relaxed weight threshold of 4" is accurate. The release adds no relaxed control for these rows.
4. **Row (7,1) has one implementation.** The paper says so. `extra/c7sym_stdlib.py` is a port, not a second
   implementation.
5. **numpy is required for 24 of the 60 checks.** (Revision 3 of the paper's Data availability said "Python 3
   (standard library)"; revision 4 states the numpy requirement.) Without numpy, 36 checks run, and
   the rows (2^4) (except the control), (2^3,1^2) auditor lift, (3^2,1^2) a = 2 and fixed-point-free, and (5,1^3) graph
   type have **no numpy-free evidence**. Pure-Python ports of these vectorised searches would be far too slow
   (for example 331 500 × 4095 weight evaluations for ℓ = 5), and C ports would be new implementations, so the release
   keeps numpy.
6. **Bound named for OA(16,6,4,2):** the paper says Bose–Bush; the auditor's re-derivation (#169) used the Rao bound.
   Both hold (`classical_bounds` prints both). No change needed.
7. **Not paper numbers, but corrected here:** argument.md 5.5(a) says of the 28 coset representatives "half give 0,
   half give 518400". The computation gives **16 and 12** (12 · 518400 · 720 = 4 478 976 000). This is noted in
   `expected/inv4_auditor_orbit.txt`.
8. **Calibrations without an original log.** The pairs S-type (type 1) calibration counts at n = 4, 6 in
   `hs_pairs_calib` are replay values of the final `dfs4b.c`. The only logged type-1 calibration came from an earlier
   version with a different normal form. The sampling calibrations (`hs_sampling`) use seed 1 with a 4σ tolerance,
   because the original seeds were not logged. Some intermediate counts of `z3fpf_pairs_rep2` (header lines only;
   its REP DONE line is in the original log) also come from the replay. None of these are paper numbers.
9. **`c5audit.py` stops by design before its own Lagrangian pass** ("too many lines", exit code 1, accepted and
   recorded by the check). Only its model-check numbers are used; the exhaustive ℓ = 5 searches are `c5graph.py`
   and `c5twist.py`.
10. **Single-author structural lemmas remain single-author.** Prop. `prop:loc`'s counting and the M-type argument were
    written by the auditor and reviewed but not re-derived by pairs. The paper says this. The release adds executable
    counts (`loc_counting_x`, `m_type_counting`), written later by the agent that assembled the release.

Every number that the paper prints in Appendix B is reproduced by at least one check, except the time-dependent
"1.4×10^6", which is reproduced only under a solution cap (item 1).
